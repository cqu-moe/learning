# 为所有错误保留可用于修复的诊断信息

2026-10-26，用户明确要求“把修复所需要的信息全都报上去，所有错误都要”，取代仅上报固定错误码和 synthetic 异常的方案。采集覆盖不以命令退出码为边界：命令、任务子项、下载、渲染、模型调用及进程异常均需考虑，被捕获后恢复、重试或降级的错误也应可追踪；按处理结果区分故障，同一异常传播不重复计为多个独立错误。

诊断应保留真实异常类型、可用错误消息、原始堆栈及 cause 链，并关联出错阶段、匿名安装身份、操作/任务/尝试、发行版本、平台与运行时。堆栈须能指向对应构建的原始源码位置；不得在上报时重新创建 Error 冒充原始抛出位置。实际没有堆栈时明确标记缺失，不编造帧。

这会改变此前完全舍弃异常原文与堆栈的隐私边界。凭据、Cookie、Token、密钥不得上传；绝对路径中的本机身份信息需移除。用户已接受必要的脱敏结构、错误位置和限长片段；完整请求/响应正文、题目答案及模型对话保留在本机，不自动上传。

构建事实：已检查的 origin/main 98a60dd 使用固定 Bun 1.4.3 直接压缩编译 TypeScript，未生成独立程序源码映射。Bun 官方文档支持将 source map 嵌入单一可执行文件并自动还原堆栈，优先验证该路径，保持现有单文件发行约定；文档支持不代表固定版本或五目标已经通过验收。历史事件中未采集的堆栈不能恢复。

用户已接受离线限量暂存、恢复后补传。暂存按目的项目隔离，仅保存脱敏后的事件；保留 7 天，最多 256 条且不超过 5 MiB，每条不超过 32 KiB，超额清理最旧记录并暴露丢弃数量。确认接收后删除，使用固定事件 UUID 应对响应丢失的重复投递；诊断自身的投递故障不递归产生异常。验收覆盖本机 Node/独立程序和五目标 CI 配置，尚未执行的目标必须明确记录；本文件不授权推送、合并或公开发布。所有实现继续通过 SDK/CLI 的既有分层，不引入通用日志/事件总线。
